# Implementation Plan: Phase IV – Local Kubernetes Deployment (Minikube + Agentic AI Tools)

**Branch**: `007-local-k8s-deploy` | **Date**: 2026-02-13 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/007-local-k8s-deploy/spec.md`

## Summary

Deploy the Phase III Todo Chatbot (Next.js 16+ frontend, Python FastAPI backend) to a local
Minikube Kubernetes cluster using an entirely AI-assisted workflow. All containerisation
artefacts (Dockerfiles), Kubernetes manifests, and Helm charts are generated via Gordon (Docker
AI Agent), kubectl-ai, or Claude Code — no manual authoring. Deployment is Minikube-only (Docker
driver, single node) and the full session is documented in `docs/phase-iv/` for reproducibility
and evaluation.

## Technical Context

**Language/Version**: Docker 26+ (container runtime), YAML (K8s manifests/Helm templates),
Python 3.11 (backend), Node.js 18 LTS (frontend)
**Primary Dependencies**: Docker Desktop 4.53+ (Gordon), Minikube 1.32+, Helm 3.14+,
kubectl-ai (GoogleCloudPlatform), kagent (LLM-backed K8s agent)
**Storage**: N/A for new storage — existing Neon Serverless PostgreSQL retained from Phase III;
no new persistent volumes in cluster
**Testing**: Shell smoke tests (`curl`/`wget` against service URL); `kubectl get pods` status
checks; Helm lint; no unit/integration tests added in this phase
**Target Platform**: Local Minikube single-node cluster (Docker driver) on Windows host
**Performance Goals**: All pods Running/Ready within 120 s of deployment; frontend page load
< 3 s on local network
**Constraints**: Single Minikube node (≤4 CPU, ≤8 GB RAM allocated); no cloud container
registry (images loaded via `minikube image load`); ≥80% of operations via AI tools
**Scale/Scope**: 2 services (frontend 2–3 replicas, backend 1–3 replicas); 1 namespace
(`todo-app`); 1 Helm chart (`todo-chatbot` v0.1.0)

## Implementation Plan

> **Constraint**: Every artefact-generating step MUST use an AI tool (Gordon, kubectl-ai,
> kagent, or Claude Code). The human role is to run the prompts, review outputs, and save logs.

### Step 1 — Preparation & Environment Verification

**Objective**: Confirm all required tools are installed and configured before any deployment
work begins. This is the US1 gate.

**AI Tool**: None (verification commands only)
**Commands to run**:
```bash
docker version                                    # Confirm Docker Desktop ≥ 4.53
docker ai "What can you do?"                      # Confirm Gordon is available → save output
minikube start --driver=docker                    # Start cluster
minikube status                                   # Confirm: host/kubelet/apiserver Running
helm version                                      # Confirm Helm 3+
kubectl-ai --version                              # Confirm GCP kubectl-ai
kagent version                                    # Confirm kagent CLI
kubectl get nodes                                 # Confirm node Ready
```
**Save to**: `docs/phase-iv/containerisation/gordon-session.md` (Gordon capability output),
terminal outputs as verification log.
**Remediation if tool missing**:
- Gordon unavailable → proceed with Claude Code fallback (document in session log)
- Minikube fails → `minikube delete && minikube start --driver=docker --memory=4096 --cpus=2`
- kubectl-ai missing → `go install github.com/GoogleCloudPlatform/kubectl-ai@latest`
- kagent missing → `brew install kagent` (macOS/Linux/WSL2) or binary from
  github.com/kagent-dev/kagent/releases (Windows); then `kagent install --profile demo`
  after Minikube starts (deploys the cluster-side controller)


### Step 11 — Helm Deployment & Lifecycle Test

**Objective**: Install the Helm chart to Minikube and test upgrade/rollback.

**AI Tool**: kubectl-ai (guidance), Helm CLI
```bash
# Uninstall raw manifests from Steps 7–8 first
kubectl-ai "delete all deployments and services in the todo-app namespace" --apply

# Install via Helm
helm install todo ./helm/todo-chatbot \
  --namespace todo-app \
  --values ./helm/todo-chatbot/values-local.yaml \
  --wait --timeout 120s

helm list -n todo-app                             # Confirm deployed
kubectl get all -n todo-app                       # Confirm pods Running

# Test upgrade (bump replica count in values-local.yaml)
helm upgrade todo ./helm/todo-chatbot \
  -n todo-app --values ./helm/todo-chatbot/values-local.yaml

# Test rollback
helm rollback todo -n todo-app
helm history todo -n todo-app                     # Confirm revision history
```
**Save to**: `docs/phase-iv/helm-chart/helm-session.md` (all commands + outputs)

## Risk Analysis

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Gordon unavailable (region/tier restricted) | Medium | Medium | Claude Code fallback documented in Steps 3–5; all Dockerfiles generatable by Claude Code |
| kubectl-ai YAML generation invalid/incomplete | Medium | Medium | Review every generated YAML before `--apply`; Claude Code corrects invalid YAML; both versions saved |
| Minikube node OOM with 2 replicas each service | Low-Medium | High | `values-local.yaml` sets low resource requests; reduce to 1 replica if needed; `minikube start --memory=6144` |
| metrics-server not providing CPU metrics (HPA fails) | Medium | Low | HPA documented as recommendation only if metrics unavailable; `minikube addons enable metrics-server` pre-emptive |
| Backend Neon DB unreachable from Minikube pod | Low | High | Neon uses public endpoint; pods use host network DNS; verify with `kubectl exec` curl from pod |
| CrashLoopBackOff due to missing env vars | Medium | High | ConfigMap created in Step 6; kagent diagnoses in Step 12; env vars verified before Helm install |
